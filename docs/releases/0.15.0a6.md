# 0.15.0a6 — online pairing and resumable HTTPS uploads

**Published and verified on 2026-10-28.** [Download the release](https://github.com/Patr1ck2005/rcn/releases/tag/v0.15.0-alpha.6).
The group's **https://rcn.my1ab.fyi** endpoint now connects to its production
center. Other operators configure their own endpoint; the generic package
contains no personal credentials or group secrets.

## Start with your Agent

Give your local Agent the repository URL and the [onboarding guide](../member-onboarding-guide.md).
It can download and verify the self-contained Setup, install it, request HTTPS
membership using your name and device, and continue the original request after
one administrator approval. The client saves personal login, registers an
independent revocable Agent credential and runs diagnostics automatically.
No private connection ZIP, preparation CMD, source checkout or SSH setup is
needed for normal membership. Contributing compute remains optional.

Administrators approve through the private console after checking the applicant
and pairing code. They explicitly attach an existing member or create a new one;
matching names never merge identities. The pairing code is only for this check.
The client protects its generated credential with CurrentUser DPAPI before
registering the digest. Pending requests expire after 24 hours; approved
credentials remain valid until revoked. Replaying a rejected, expired or revoked
request does not restore access.

Visible joining and explicit CLI waiting use five-second polling. Closing the
page stops polling; reopening resumes the original request. Sign-out durably
pauses automatic continuation. Successful diagnostics are reused. Existing
Agent state, jobs, downloads and owner pauses survive upgrade; ZIP and managed
SSH remain available as advanced recovery paths.

## Transfer and deployment

HTTPS uploads use 8 MiB sequential chunks, one writer and one partial file.
Confirmed offsets survive lost responses and restart. Full content verification
precedes atomic publication; verification can continue outside the initiating
request. The original Job and operation identities are retained. A center that
lacks the required upload capability produces an upgrade message, without
silently falling back to a large whole-file upload.

Result downloads retain Range support and durable collection. The Tunnel has
no scientific-data cache. Public routes require authentication where applicable,
private administrator routes remain excluded, and responses use `no-store`.
The existing database, execution profiles, transmission budget and worker
configuration are reused. This release adds no broker or account platform.

The independent Agent completed the installed workflow through verified result
collection; the main agent performed the final replay and hash checks.

The 8 GiB exercise is an isolated boundary test, not a public-network throughput
claim. Synthetic fixtures execute integer-square outputs, not COMSOL science.
No production simulation or load test was added. Some immutable offline help
was packaged before acceptance and still says pending; this dated release
record is the final status. Its operation and recovery instructions remain valid.

Unfamiliar Windows hosts, UAC interaction, host reboot, new-member scientific
trials and purchased code signing remain deferred. Local installed tests do not
establish those outcomes. Licensed solvers, scientific templates, project data,
sealed scientific runtimes and private production state are not included.
