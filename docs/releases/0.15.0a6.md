## Changes

The normal member route becomes GitHub Releases → Windows Setup → HTTPS `join`
→ one approval through the group's private administrator interface → automatic
personal login, independent Agent credential, configuration and diagnostics.
ZIP and managed SSH remain advanced recovery paths for existing identities.

Pairings retain the original UUID and content through lost responses and
restarts. The client protects a generated secret with CurrentUser DPAPI before
registering its digest. A short pairing code is only a human identity check.
Administrators explicitly attach an existing member or create a new one;
display-name matches never merge identities automatically. Rejected, expired
and revoked requests cannot be reactivated by replay.

Pending approval uses five-second polling with a bounded CLI wait. Sign-out
pauses automatic pairing continuation durably. Explicit resume retains the
original request. Interrupted diagnostics can resume, failed diagnostics need
an explicit retry, and successful reports are reused.

The transfer update introduces bounded resumable input uploads for HTTPS
ingress. Interrupted uploads retain the original Job and content identity;
an unavailable required resumable protocol must fail without a whole-file
downgrade. Actual delivered-byte and recovery acceptance is still pending.

## Endpoint configuration

Generic operators configure their own verified HTTPS endpoint using
[`config/member-ingress.example.json`](../../config/member-ingress.example.json).
The example contains no credential and is disabled until configured by its
operator. Public member routes and private administrator operations remain
separate. See the [operator configuration section](../member-onboarding-guide.md#操作员配置公开-https-入口).

This research group's intended endpoint is **https://rcn.my1ab.fyi**.
Its configuration is separate from the generic example, and its availability
remains **pending** this round's public HTTPS acceptance.
